## 1. 目标与优先级

原始目标：**扫描 `doc/design` 下的设计文档，保证与代码同步，并完成仍有效的未完成任务。** 历史上明确被取代的方案不重新实施；不能把尚未实现的要求改成“范围外”来宣布完成。

架构方向：Tauri 与 CLI 尽量共用执行核心，CLI 作为无界面入口；核心行为优先通过 CLI 验收，Tauri 额外验证平台/IPC/界面，不各自维护一套 harness。

用户后续明确的第一优先级是最小可运行系统：

1. Durable Kernel：持久 Task/Effect、结果重开、取消和恢复。
2. Skill：加载、持久身份、指令进入 harness/Agent 上下文。
3. DAG：至少一个简单的多节点图及节点间传值。
4. **Tauri 提供 Bash tool**，最终 harness 经标准 `tool.call` 调用 Bash/Bash 命令，启动子 harness，子 harness 执行简单 DAG，并回传输出和退出状态。
5. Web 暂保留平台接口，不启用本机 Bash。

跨 Session memory、完整 Skill 自动委派等扩展后移，原目标和其他有效待办继续保留。

验收链：`Tauri 外层 harness → Kernel tool.call Effect → Bash tool → 原生 Bash → CLI 子 harness → 简单 DAG → 输出/退出状态/持久记录`。

- **发现的真实缺陷**：同一轮在宿主重启后只剩一个**没有状态、没有原因**的空助手气泡。根因是五处不同步：`round-graph-service` 只在 `failed` 时写 `error`；`failRound` 只对 failed 传原因；`session-state` 的占位符条件写 `'aborted'` 而 Round 状态是 `'cancelled'`；`branch-service.assistantGroup` 重建时丢掉 `error`；`NodeRenderer` 只在 `failed` 渲染错误行。
- **修复与回归**：五处对齐（终态判定 `failed|cancelled`、占位符状态映射为 `aborted`、重开分组带 `error`、`aborted` 也渲染错误行）；llm-session 新增两条持久化/投影回归（97→**99**），整仓 `pnpm test` → `=== full matrix passed`。
- **真机复验**：重开后同一轮显示 `Assistant` + `ABORTED` + `⚠️ Task cancelled: task_0caa7eb7-…`，随后新消息照常发送。证据 `.tauri-acceptance/round82-cancel-live.log`、`round82-cancel-reload.png`。
- **仍未完成**：超时取消、授权撤销、IPC 错误、Session 关闭在真实窗口的 UI 表现；发送延迟仍 4.4s/≈590 次 IPC。详见 [验收记录 §23](../minimal-system-acceptance.md)。

**2026-09-11 第八十三轮：真实窗口的授权撤销（GUI `卸载`）+ 一个工具节点状态缺陷**。（第八十六轮补：`改为只读` 也已在真实窗口取证——读仍通、写被隔离层拒绝、宿主文件未变，见 [验收记录 §25](../minimal-system-acceptance.md)。）

- **撤销链路**：会话 `files` 视图的挂载对话框每行有 `卸载`/`改为只读`/`设为工作目录`/`重新连接`；点 `卸载` 后 `files` 记录变为 `mounts: []`、`cwd: "/"`，`files` 视图回到「尚未挂载工作目录…」，宿主目录内容保留。
- **撤销后访问被明确拒绝**：Bash 仍被广告，但执行被 Rust 守卫拒绝（`Session Bash requires a mounted Session directory; …`）；内核 Task `failed`、轮次 `failed` 且持久化该消息、界面 `⚠️ 执行失败`，会话仍可继续发送。证据 `.tauri-acceptance/round83-revoke-*`。
- **同轮发现并已于第八十四轮修复的缺陷**：成功路径工具节点显示 `SUCCESS`；但**工具 Effect 失败**（撤销后跑 Bash）时 live 节点停在 `🔧 Bash RUNNING`（协调器只在 queued/running 建节点，Effect 失败没有任何 `tool:*` 终态事件）。修复：`failRound` 对未结算的工具调用补发终态 `tool:error`（`unsettledToolErrors`），回归 `tool-failure-settlement.test.ts` 3 条（llm-session 99→102），真机复验节点变为 `🔧 Bash FAILED`。**该信息损失已于第八十五轮修复**：`failRound` 把已开始的工具调用写入轮次 `result`（未结算记为 isError + 失败原因），投影的失败占位符带上 `toolCalls`，重开后转录仍显示 `🔧 Bash FAILED` 与守卫消息（llm-session 102→105，真机复验见 §24.7）。详见 [验收记录 §24](../minimal-system-acceptance.md)。

## 4. Memory 的“Session 间共享”含义

跨 Session 共享指 Session B 在**明确授权**后读取 Session A 或项目共享区保存的记忆；通常需要独立于单个 Session 生命周期的存储、来源身份、读写策略及冲突处理。

目前的 `SessionMemoryProvider` 把条目保存在当前 Session 的 shared state，按 namespace/scope 管理并用 CAS 写入。这里的 shared 是**Session 内的共享状态**，不表示所有 Session 自动共享；同一 namespaceId 也不会隐式跨 Session 访问。当前是词项匹配/更新时间排序，尚无模型写入工具与长期语义记忆系统。用户已要求这部分后移，先完成最小系统。
