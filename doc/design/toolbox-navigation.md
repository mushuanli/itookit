# 工具箱导航

Web 与 Tauri 共用 `ToolboxWorkbench`，主导航中用「工具箱」集中展示智能体、技能、流程、模型连接、服务商、MCP 和工具。

## 交互

- 一个 vfs-ui 单列列表、一处搜索、七个分类筛选（全部、智能体、技能、流程、模型、MCP、工具）；筛选不会关闭正在编辑的内容。每类记住搜索词。目录优先，资源固定按名称自然升序排列（数字按数值、中文按中文本地排序）；同名用资源路径稳定决胜，点击、刷新和使用时间不会重排。
- 每行展示类别图标、名称和用途；不重复显示类型标签。图标提供悬停提示和读屏标签，服务商优先使用用户自定义图标，内置默认图标使用 SVG 字母标识，未知服务商使用通用图标；连接统一用链环、设置用调整图标。所有资源以一层抽屉展示。原有智能体与流程目录按路径展平成抽屉名称，文件位置不变；默认目录中的条目归入「未分组」，系统提示词由设置管理。搜索覆盖折叠抽屉中的资源。
- 共用工具栏提供新建、导入、导出和整理条目。新建对话框选择智能体、技能、流程、模型连接、服务商或 MCP；智能体、技能、流程与 MCP 可搜索选择本类已有抽屉，也可直接输入新名称，提交成功时一并建立分组。当前抽屉自动继承，取消不产生空抽屉。模型仍通过服务商分组；对应原有专用编辑器。MCP 直接打开所选连接表单，避免再套一层列表。
- 工具由运行时目录及 MCP 已发现能力提供，工具实现和参数定义保持只读；详情的使用配置可以选择智能体并保存授权。内置工具写入该智能体的 toolIds；MCP 工具写入来源连接的 mcpProfileIds，表单明确说明授权该连接全部工具。保存保留其他策略字段，不绕过宿主和项目权限。详情显示说明、参数、启用状态、来源，MCP 工具可跳转到对应连接。列表不会连接 MCP，也不会执行工具。
- 移动端沿用列表/内容切换与返回列表按钮，不增加第二层侧栏。

模型按服务商显示抽屉，第一项为设置，下面是该服务商的连接。已配置且启用、未配置、禁用、缺失服务商按组排列，组内固定按名称排序。配置状态仅指凭据是否已填写（Codex 使用本地认证），不表示联网检查成功。抽屉显示连接数和状态；新建连接默认使用当前选中的服务商，也可在对话框改选。打开资源链接会展开所属抽屉，呈现单项表单；连接可直接跳转所选服务商。

工具按文件、网页、记忆、任务、终端、协作、技能与扩展分抽屉，MCP 工具按来源服务分组。各类使用不同图标并显示工具数。通过整理条目可批量分配工具到自定义抽屉，不改变工具来源、实现或授权。抽屉使用浅色标题底、固定箭头位置及加粗名称；内容区缩进并显示细导线，选中项独立高亮。分组在「全部」和专属分类中一致，搜索自动展开匹配项，点击不会改变排序。设置页移除 Provider、Connection、MCP 重复入口；未配置工具箱的宿主仍可使用独立设置编辑器。

抽屉右侧与条目旁的更多操作按钮支持触屏与键盘。抽屉可新建条目、重命名和删除；删除只将内容归入「未分组」。条目可单独或同类多选后移动，整理弹窗支持切换类别、搜索、全选和清空。抽屉、单项和多选菜单均使用统一「导出 JSON」操作，顶部导出按钮走同一归档流程；工具分类也提供导入以恢复工具引用与分组。智能体、技能、流程保留原 VFS 单项／批量删除操作。MCP、连接及自定义服务商的列表删除通过宿主 `EditorHostContext.requestDelete` 调用共享确认界面与应用命令，无需打开编辑器。模型抽屉菜单提供设置、导出和删除，内置与自定义服务商使用同一关联影响确认：同时删除关联连接，受影响的智能体可替换连接、保留待修复或一并删除。内置服务商沿用底层删除标记，重启后不会自动恢复；默认连接沿用原有保护，涉及它时须先更换其服务商。不同类别允许同名抽屉，「全部」视图用小型类别说明区分，不增加目录层级。

## 路由与存储

规范地址为 `#/toolbox/<encodeURIComponent(资源路径)>`，资源路径带 `/agents`、`/skills`、`/flows`、`/mcp`、`/tools`、`/providers` 或 `/connections` 前缀。例如 `/agents/default/example.agent`。旧 `#/agents`、`#/skills`、`#/flows` 链接与导航请求会转换到工具箱，保持原文件路径。旧 `#/settings/providers`、`#/settings/connections`、`#/settings/mcp-servers` 及携带 anchor 的设置导航请求重定向到工具箱分类或具体条目。

`app-core/configuration` 管理资源操作、分组存储与只读目录；`ToolboxWorkbench` 用 `createFileSystemView` 挂载已有资源源。适配层向编辑器传回原始路径/实体 ID 和所属文件系统；原有智能体、技能、流程及 MCP 存储无需迁移。MCP、工具、Provider 和 Connection 使用只读内存投影，配置修改仍经过管理服务；投影不包含模型服务商凭据。`SkillsEngine` 提供可挂载的根目录。`/drawers/*`、`/model-groups/*` 和 `/tool-groups/*` 仅是 UI 抽屉，不改变存储目录或文件身份。

自定义抽屉名称、资源归属及默认分组调整持久化在 `/etc/ui/toolbox-drawers.json`，Web 和 Tauri 共用 VFS 读写。资源重命名时同步更新归属；保存失败不更新内存分组，新建资源的分组保存失败会回滚本次新建资源。

工具目录仅向 UI 暴露 `listTools`、定义及元信息，不暴露调用入口。目录中的启用状态不代表当前会话已获授权；实际可用性仍由宿主、项目权限及运行时决定。

## JSON 交换

`itookit.toolbox` v1 归档包含所选资源的 `kind` 与 `data`。选择抽屉会导出其条目；服务商抽屉包含配置及连接，工具抽屉包含工具引用。条目的可选 `drawer` 字段保存抽屉名，顶层可选 `drawers` 保存选中的抽屉（包括空抽屉）。导入按类别复用同名抽屉，新增资源重映射后的 ID 归入原抽屉；旧版无分组归档仍兼容。智能体、技能、流程、MCP、Provider 和 Connection 导入为新 ID，保留原资源；流程按草稿保存，允许继续编辑未完成的草稿。MCP 副本初始断开且不自动连接，已发现能力由重新连接后获取。

工具条目是描述与来源引用，导入只解析当前已存在的工具；缺少来源则在写入其他资源前报错。定义和抽屉组织支持往返，不等于运行状态或原始 ID 的原地恢复。导入总是为可编辑定义生成新 ID；MCP 运行状态与发现的能力由重连获取，工具实现不会包含在 JSON 中。历史目录生成的长抽屉名在导入时完整保留。归档内同时选中的 Provider → Connection → Agent 引用映射到新 ID；未选中资源及其他外部引用（工具 ID、其他智能体等）保留原值。此格式用于定义交换，不是包含全部依赖、运行记录和凭据迁移的安装包；MCP 配置导出会包含其配置字段，应按配置文件保管。

跨类型用途分组、收藏和完整依赖迁移尚未实现。

## 实现与验证

- `packages/app-shell/src/toolbox/`：模块装配、列表、纯展示投影和路由转换。
- `packages/app-core/src/configuration/`：资源操作、分组快照、只读目录、引用重映射与失败补偿。
- `packages/llm-settings-ui/src/editors/MCPSettingsEditor.ts`：连接表单模式及原设置页模式。
- `packages/vfs-ui/src/ui/components/NodeList/NodeList.ts`：可注入列表投影/筛选头，动态工具栏；其他模块默认行为保持一致。
- `packages/app-shell/tests/toolbox-workbench.test.ts`：资源筛选、抽屉排序与搜索展开、服务商图标、新建连接归属、编辑器身份、归档复制及工具来源检查。
