# 项目抽屉与子会话导航

状态：首版已实现，2026-09-26。实现契约见 [Session 浏览投影](vfs-session-browser.md)。下文同时保留明确标注的后续能力；窗口渲染、显式引用父历史和递归删除尚未实现。

## 1. 目标与决定

项目收纳文件和会话。会话可以创建独立的子会话，子会话也可以继续创建子会话；用户不必沿父子关系逐层进入页面。

采用“项目抽屉 + 同组会话列表 + 正文”：项目抽屉只列文件入口和顶层会话；同组列表平铺一个顶层会话及其全部后代。切换组内任何会话时列表范围不变，只替换正文及当前选择。没有子会话时收起这一辅助列表，首次创建子会话后自动出现。

“同组”是一个顶层会话及其后代的显示方式，不引入需要用户另行创建、命名或管理的分组实体。父会话始终有自己的聊天正文。

## 2. 桌面结构

```text
项目抽屉                  同组会话                  正文
──────────────────────   ──────────────────────    ────────────────────
▾ 旅行计划                旅行讨论 · 4 个会话         备选酒店
  文件                    [搜索本组]                属于：酒店预订
  旅行讨论 (3)            旅行讨论 · 主会话           [+ 子会话] [更多]
  签证资料                行程安排                  聊天记录与输入框
  + 新会话                酒店预订
                         备选酒店 · 属于酒店预订
▸ 学习计划
```

示例中“旅行讨论”是顶层会话，有两个直接子会话“行程安排”“酒店预订”；“备选酒店”是“酒店预订”的子会话。抽屉中的 `(3)` 表示所有后代数量；组标题的 `4 个会话` 包含顶层会话本身。

- 点项目标题展开/收起卡片，不额外打开项目详情页，不切换正在编辑的正文。允许多个项目保持展开，记住展开状态。
- 文件入口始终是项目内第一项，固定只有一个。点它后，辅助列展示文件树，正文展示选择的文件；从聊天切到文件时恢复上次文件位置。
- 文件入口下面是顶层会话；点击整行打开该会话的正文及同组列表。数量徽标仅提示后代数量，与标题共用同一点击行为，避免同一行出现不易区分的两种打开方式。
- 顶层会话没有子会话时，直接打开正文，不显示空的辅助列。创建第一个子会话后，辅助列显示父会话和新会话并选中新会话。
- 同组列表始终包括根、父、兄弟及其他后代，不随当前选择变成“当前会话的孩子”。当前会话的直接子会话可用轻量标记提示，不重新排序整个列表。
- 所有成员采用相同左对齐；间接后代显示“属于：父会话名”。根会话固定第一项，其余按创建时间排列；发送消息不改变位置。搜索可以匹配标题及父会话标题，清空搜索恢复原位置。
- 当前会话的父会话标题可以直接点击，完整祖先关系放在更多菜单的归属信息中。过长标题截断，完整名称可通过焦点或悬浮查看。
- 抽屉显示组内运行/待处理状态汇总；同组列表标记具体会话。折叠项目不会停止运行。
- 辅助列可收起；正文标题旁保留“同组会话”按钮。文件树与同组列表复用此列，不再分别增加侧栏。

### 为什么不直接画无限会话树

无限树会同时增加缩进、展开动作和横向空间要求。只有当前会话的子列表则会使兄弟会话消失，用户需要反复返回。固定范围的同组列表让深层会话可以直接访问，父标签保留归属信息。

平铺也有代价：一个组的会话很多时，列表会变长。因此需要组内搜索、定位当前会话、可滚动列表；规模较大时使用窗口渲染。不得通过隐藏部分后代且没有提示来换取短列表。导航阶段只加载会话摘要，不读取各会话正文、附件或任务历史。

## 3. 创建与整理

| 入口/动作 | 结果 |
| --- | --- |
| 项目抽屉“+ 新会话” | 在该项目创建顶层会话并打开 |
| 正文标题“+ 子会话” | 在当前会话下创建独立会话并打开；同组列表保持范围 |
| 会话行更多菜单“新建子会话” | 明确以该行会话为父，不依赖其他区域的选中状态 |
| “移到其他会话下…” | 搜索选择同项目内的目标父会话，连同当前会话的后代一起移动 |
| “移到项目顶层” | 清除当前会话的父关系；其后代随它成为新的一组 |
| 重命名 | 原地修改名称，不改变 ID、父关系或正文 |
| 删除当前会话 | 明确提示只删除此会话；直接子会话提升到被删会话的父级，后代保留 |

新建后直接进入可输入的空会话，使用默认名称并允许内联修改；无需先填写创建弹窗。创建中的按钮防止重复提交，失败时保留原会话和草稿。

创建入口必须写清“新会话”或“子会话”，不提供根据焦点暗中改变行为的通用加号。常用入口只有项目的新会话和正文的子会话；移动、归属信息、删除收进更多菜单。拖拽可以后续补充，所有整理操作必须能通过菜单完成。

首版不提供一键递归删除整组。批量删除沿用明确选择的会话集合，确认框展示数量及保留后代的处理方式，不能把未选择的后代隐式加入删除集合。

### 目录如何共存

保留已有项目分组和会话目录。项目分组收纳项目，项目内部的会话目录收纳顶层会话；子会话通过父关系归属，随顶层会话一起移动目录。新建流程不要求先建目录，也不在每个子会话下再增加会话目录。

旧目录及现有会话完整保留，不自动移动或转换为父子关系。项目内搜索应能直接命中目录深处的顶层会话和子会话，并展示所在项目、目录和父会话；打开结果直接到正文并定位同组列表，不要求先逐层展开目录。

### 统一工具栏与数据交换

- 项目列复用 vfs-ui 的创建目录/创建文件位置，显示「＋项目」「＋会话」；不再额外渲染“新建项目/项目分组”顶栏。
- 文件列同一位置显示「＋目录」「＋文件」，使用原有 VFS 内联命名和权限检查。标题显示当前项目名称；窄屏返回入口叫“项目列表”。
- 同组会话列显示「＋项目」「＋子会话」，后者明确在当前会话下创建。收起列表是标题栏的小按钮。
- 四个按钮保持一排：两个带名称的创建按钮、两个带工具提示和无障碍名称的导入/导出图标；窄屏仍保留全部操作，触控高度 44px。
- 导出使用该列的选中项；没有显式选择时使用当前项。项目包括文件树和全部会话；会话包括其后代。同时选择祖先与后代时去重。
- JSON 格式为 `itookit.workbench` version 1，入口见 `app-core/src/projects/workbench-archive.ts` 与 `workbench-import.ts`。`items` 支持 `project`、`group`、`session`、`files`；项目/分组/会话通过 `children` 表达组织关系，文件以相对路径和 Base64 内容表达。
- 项目文件包含隐藏文件、SeqFile 记录、文件关联资源；会话包含历史、草稿、设置、分支索引及嵌套附件。也接受已有的 `itookit.session` v2 和旧版会话 JSON。
- 导入前验证整个归档。项目导入到当前项目所在分组，会话导入到选定项目/会话目录，文件导入到选定文件的父目录或选定目录。始终创建新副本，同名项目/目录/文件加数字后缀；导入失败回收本次已创建的内容，清理失败显式报错。
- 导入的项目使用新的托管目录，不照搬导出机器的绝对路径和挂载授权；会话 ID、存储修订及更新时间按本地新记录生成。归档保存用户内容和组织关系，不恢复正在运行的 Kernel 任务或外部进程。

## 4. 上下文与文件

每个子会话有独立 ID、历史、分支、草稿、任务及附件。父子关系只表达收纳，不触发执行，也不自动拼接祖先聊天历史。

新子会话默认按所属项目的新会话规则初始化，可以访问该项目已授权的共享文件。父会话额外授权的目录、运行态及临时上下文不因父关系自动继承。项目仍只有一个常用文件入口，会话附件及特殊挂载放在会话的更多菜单中。

创建后在空态简短提示“独立会话，共用项目文件”。未来可提供明确的“引用父会话中的内容”操作，记录用户选择的内容快照及来源；不默认复制全部历史。既有聊天分支继续表达同一会话内部的历史分叉，子会话使用独立的关系字段。

## 5. 窄屏与键盘

手机保留“项目抽屉”和“正文”两个主要界面。从抽屉点会话直接到正文，子会话切换使用正文标题的“同组会话”面板，选择后关闭面板。面板可以直接选择任何后代，不添加按深度累计的页面。

正文返回按钮回到项目抽屉并恢复滚动位置；“属于：父会话”用于切父会话，二者明确区分。浏览器后退仍按实际访问历史回放，不强行改为父级导航。文件入口直接显示文件列表，打开文件后可以返回文件列表。

抽屉标题提供 `aria-expanded`，会话选择提供当前项语义，所有按钮可用键盘触达。切换面板打开时聚焦当前会话，关闭后归还触发按钮；Escape 关闭临时面板。新建会话后聚焦输入框。

## 6. 数据与组件边界

Session 元信息增加可选 `parentSessionId`，缺省或 null 表示顶层会话。继续使用独立 Session 的既有物理存储路径，项目文件目录、MindOS profile 根目录均无需搬迁。不要把该字段写入历史索引。

约束：

1. 父会话必须存在，且与子会话属于同一项目；不能指向自己或任何后代。
2. 一棵会话树共享顶层会话的目录归属。更换父会话跨目录时，同事务更新整棵待移动子树的父引用和目录字段；同目录重组仅更新必要的父引用。
3. 父关系和目录归属通过专门的操作验证，不能被普通标题/草稿更新绕过。并发改变归属时在提交前重验关系，不能只依赖界面禁用目标。应用运行时为结构修改取得受影响会话的写租约；拒租时不写入关系。
4. 不持久化第二份 children 或 rootSessionId 权威数据；从摘要构建父子索引并缓存，避免多份关系互相矛盾。对持久化修改做一致性通知。
5. 旧数据没有父字段时全部按原位置的顶层会话显示。缺失父引用、循环或跨项目损坏关系必须能在恢复入口看到有关会话，不允许投影无限递归或静默隐藏；正常写入拒绝这些关系。
6. 会话资源身份继续以 Session ID 为准，父关系不能编码成必须逐级解析的新 URL。旧目录限定链接继续兼容；父关系改变不改会话 ID，重命名不改链接。
7. 单独导入会话默认成为目标目录的顶层会话，不照搬可能指向本地无关会话的父 ID。整组导入为每个成员创建新 ID，按归档中的父子结构重建引用。

职责划分：

| 层 | 职责 |
| --- | --- |
| `llm-session` | 持久化父引用、关系事务、独立历史及草稿 |
| `app-core` | 项目边界校验、会话树查询/变更、创建与删除生命周期、浏览投影 |
| `app-shell` | 项目抽屉、固定范围的同组列表、创建目标、路由及窄屏行为 |
| `vfs-ui` | 可选单双列、卡片展开、列表投影、搜索/选择/键盘等通用机制 |
| `llm-ui` | 聊天正文，通过宿主动作创建子会话或显示同组面板 |

Web 和 Tauri 使用同一套宿主逻辑。其他模块不配置双列时继续保持单列；vfs-ui 不需要认识 Session 父子业务。

### 删除与失败恢复

已有删除流程会先关闭执行，再删除 Kernel 和 Session 存储；物理文件删除不能与关系元数据天然形成单个原子事务。实现使用 `folders.seq` 中的删除意图连接这些步骤，不把关系元数据事务当作物理删除事务。

停止失败时不删除正文或改变父关系。停止成功后，在同一事务中记录原父关系、直接子会话集合并完成关系提升，然后删除 Kernel 与 Session 存储，最后清除意图。物理删除失败时已提升的孩子仍然可见，重新执行不会重复改变归属；启动在取得待删会话租约后重试清理，并排除其执行恢复。待删除会话禁止再挂入新子会话，并发关系操作须重验状态。发生后续清理失败时保留明确的可重试状态，项目导航提供“继续清理”入口；未删子会话始终能从导航访问。

首版删除保留后代。递归删除作为后续独立能力，避免用“一个目录递归删除”替代多个独立会话的生命周期管理。

## 7. 实现范围与验收

1. 先补父子模型和操作约束，覆盖创建、循环拒绝、同项目移动、提升、旧数据读取、独立历史/草稿及删除故障恢复。
2. 项目抽屉固定文件首项，隐藏内部 `@sessions` 容器；接入顶层会话与后代数量。保留已有分组目录。
3. 接入固定范围的同组列表、直接创建子会话、切换及归属菜单，更新现有工作台测试；不混用聊天分支。
4. 验证窄屏、键盘、浏览器回放、刷新恢复及 Web/Tauri 共用行为；最后移除旧会话/文件 tab 所造成的重复入口。

关键验收场景：

- A → B → C → D 连续创建：抽屉只有 A，同组列表一次展示四个会话；A 与 D 相互切换只需一次选择。
- 打开 B 后仍能直接看见并选择 A、C、D；新建 B 的子会话时不清空其草稿。
- 删除 B 后 C 提升到 A 下，D 仍属于 C；遇到停止失败或清理中断，未删除会话可见且能恢复处理。
- 把 B 移到顶层后，C、D 跟随 B；原组与新组计数更新，正文保持 B。
- 跨项目移动、把 A 移到 D 下、与删除并发挂入子会话均被拒绝，持久化后没有循环或悬空引用。
- 打开旧链接、中文项目名和刷新深层会话都能直接恢复正文，物理目录不发生迁移。
- 项目只有一个常用文件入口；会话列表加载不枚举全部任务、附件或聊天历史。
- 手机从项目抽屉直接进入 D；切到 A 只打开一次同组面板，不连续返回三层。
