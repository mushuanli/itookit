# 数字分身设计

状态：设计提案，尚未实施。更新日期：2026-10-09。

数字分身从用户选择的文件、会话、笔记与邮件中维护个人画像、记忆和目标，提供可追溯、可纠正、可遗忘的个人知识。Pot 持续关注来源与目标，调用现有 Agent 或 Flow 完成分析和整理。第一期创建一个分身管家 Pot，完成来源登记、增量分析、人工确认和删除联动，再扩展自动触发及外部来源。

本文定义目标行为与验收契约；文中的新类型、接口及存储对象均为提案，不代表已有 API。

## 现有基础与实施边界

| 现有能力 | 可复用范围 | 数字分身需要新增 |
| --- | --- | --- |
| 工作区导航与原生 DOM UI | 新导航装配、列表与编辑界面 | 数字分身工作区及视图 |
| Session 本地及共享 Memory | 授权、CAS 条件写入、审计、幂等回执 | 来源登记、证据关系、候选与遗忘状态 |
| VFS 文件元数据与事件 | 修改时间、创建、更新、移动和删除通知 | 持久变更消费与完整扫描核对 |
| harness 原生历史与分页 | 原生会话及消息身份、分页读取 | 按轮次增量提取和覆盖范围 |
| 项目目录 watcher | 变化版本及缺口提示 | 变化后的来源差异核对 |
| Durable Task 与 Flow | 执行、预算、检查点、恢复及交互 | Pot 触发策略与运行装配 |

已有邮件工作区用于邮件草稿；真实邮箱需要独立来源适配器。私密工作区的保护标识不构成数字分身的读取授权，也不保证所有派生数据已经加密。跨 Session Memory 仍有系统验收待办，分身实施应继承其契约与限制。

相关基础见 [共享 Memory 契约](p2-completion.md)、[Session API](../llm-session-api.md)、[事件流](../event-flows.md)、[项目与 harness 模型](pi-agent-project-model.md)。语义和向量检索继续延期，第一期使用结构化过滤及词项检索。

## 导航与信息内容

新增顶层「数字分身」导航。第一期包含五个页面，待确认入口在概览和记忆中共用。

| 页面 | 内容与操作 |
| --- | --- |
| 概览 | 近期变化、分析覆盖范围、当前关注事项、待确认数量、Pot 状态 |
| 个人画像 | 身份、长期偏好、工作习惯、能力及沟通风格；查看证据、确认、纠正 |
| 个人记忆 | 事实、经历、决策与原因、经验；搜索、编辑、查看来源、遗忘 |
| 目标与关注 | 长期目标、近期计划、承诺、未完成事项、提醒条件 |
| 来源与设置 | 来源选择、读取与处理权限、Pot 配置、更新记录、错误及预算 |

后续可将项目背景、相关人物及合作关系独立为「项目与关系」，但必须区分本人信息与第三方信息。画像是有效记忆的聚合投影，记录依赖的记忆版本；用户的直接修改通过确认或纠正记录进入权威数据，不建立一套脱离来源的平行画像。

每条记忆显示内容、证据、有效时间、确认状态和敏感范围。模型给出的置信度仅用于审阅排序，不构成事实验证。历史事实可以保留原有效区间，当前画像只使用当前适用的记忆；矛盾信息进入待确认，不按最新时间静默覆盖。

## 来源与授权

来源范围由用户显式选择，默认不扫描所有可见项目。来源适配器统一提供授权范围内的枚举、元数据、内容分页与变化提示。

| 来源 | 身份与读取方式 |
| --- | --- |
| 工作台文件和笔记 | VFS 授权视图、所属项目与挂载身份、文件身份或路径及创建代次 |
| MindOS Session | 稳定 Session、分支、消息和轮次身份，读取持久历史 |
| harness Session | MCP 连接、server、project、profile、native Session 的完整身份及原生历史页 |
| 邮件草稿 | 现有文件来源，明确草稿而非已发送邮件 |
| 真实邮箱 | 后续适配器，使用账号、邮箱及消息身份，不按主题去重 |
| 私密内容 | 独立授权范围、允许的处理模型、派生数据保存与使用规则 |

读取授权、模型处理授权、派生数据检索授权分别记录。私密内容被允许提取，不自动允许进入普通 Agent 会话，也不自动允许发送到云模型。锁定、撤权或来源断开后，相关读取和检索立即受限；正在执行的任务在提交前再次校验策略版本。

源文件、邮件正文和历史消息均为待分析材料，其中的命令不能修改 Pot 配置、扩大授权或触发外部操作。模型只返回结构化候选结果，宿主校验证据引用、权限和版本后才提交。

## 数据模型

建议使用以下独立对象，来源正文继续由原有系统管理。

| 对象 | 关键字段 |
| --- | --- |
| Twin | twinId、所有者、revision、共享 Memory 引用、Pot 引用及默认策略 |
| SourceBinding | bindingId、完整来源范围、grantRevision、处理模型限制、敏感范围、删除策略 |
| SourceRecord | sourceId、incarnation、当前位置、revision、mtime、size、contentHash、发现与检查时间、来源状态 |
| SourceCheckpoint | 最近完整扫描代次、事件游标、已分析版本、历史分页或轮次游标、覆盖范围 |
| Evidence | sourceId、incarnation、sourceRevision、分支、消息或片段定位、引用摘要、证据类别 |
| MemoryEntry | memoryId、不可复用 revision、内容、类别、有效时间、敏感范围、证据集合、确认及冲突状态 |
| ReviewDecision | 决定身份、对象版本、确认或拒绝或纠正或保留或遗忘、适用范围及操作者 |
| ProfileProjection | profileRevision、画像字段、依赖的 memoryId 与 revision、覆盖范围及生成时间 |
| PotDefinition | 持续职责、Agent 或 Flow 引用、来源范围、触发规则、目标、预算和行动权限 |
| AnalysisJob | 幂等键、目标来源版本、提取规则版本、检查点、状态、租约、回执、费用与重试计划 |
| SourceTombstone | 来源身份及代次、删除或遗忘原因、操作身份、revision 和必要时间 |

sourceId 不仅是文件路径。无法获得稳定文件身份时使用授权命名空间加规范化路径，并维护创建代次；路径删除后重建形成新 incarnation。仅凭 hash 相同不能证明文件发生移动。已知移动通知可以迁移当前位置，身份不明的移动按新增与缺失核对处理。

证据允许一条记忆关联多个来源。修订、删除或撤权通过证据反向关系定位受影响记忆和画像，不依赖模型再次猜测关联。墓碑不保存原文。来源清单、证据及拒绝记录本身也继承敏感范围，不能因属于元数据就对所有会话开放。

## 修改检测与增量更新

修改时间用于筛选更新候选；权威 revision 或内容 hash 用于确认内容变化。mtime 可能精度不足、被复制保留或回拨，因此不能作为唯一水位。先使用 mtime、大小、版本和事件降低读取成本，再定期执行授权范围内的完整核对；没有可靠内容版本的来源应安排有界内容校验。

```mermaid
flowchart LR
    A[授权来源] --> B[来源登记与变化检测]
    B --> C[文件片段或完整会话轮次]
    C --> D[Agent 提取候选记忆]
    D --> E[宿主校验来源版本和权限]
    E --> F[确认 去重 冲突处理]
    F --> G[记忆与画像]
    G --> H[Pot 关注目标并生成建议]
```

处理流程为：发现候选变化，读取并固定来源版本，比较内容摘要，分析受影响片段，校验结构化结果，提交证据与记忆，最后推进已分析版本。同一内容仅更新时间变化时跳过模型分析。规则或模型版本变化可产生重新分析任务，但不得绕过既有人工决定。

只有结果提交成功才推进检查点。任务幂等键至少包含来源身份、incarnation、目标内容版本和提取规则版本。读取期间发生修改时，在提交前核对版本；无法获得版本化读取的来源使用前后元数据及内容摘要核对，并明确其一致性限制。

工作台的「2 分钟内近期活跃」仅是状态展示推测，不作为分析完整性、任务结束或增量同步的依据。分身的「最近检查」「最近成功分析」「源内容更新时间」分别显示。

## 删除追踪与遗忘

来源清单与持久变更记录都需要保留。前者记录分身分析过哪些对象，后者记录操作及消费进度。现有 VFS 事件作为通知入口，不能直接假设为完整持久日志；新增服务应将相关通知持久化，记录消费游标。外部修改、应用关闭期间的操作及 watcher 缺口通过完整扫描核对补齐。

一次扫描必须固定授权范围、绑定身份与扫描代次。分页全部成功且枚举完整后，才将清单中未发现的对象标为删除候选。网络失败、权限不足、来源断开、扫描截断或绑定变化都不能转为删除。扫描没有一致快照保证时，对缺失对象再次查询或执行下一次完整核对，避免分页期间的移动导致误判。

文件移动、Session 归档、临时卸载和撤权使用不同状态。归档可以停止后续更新，但不自动删除已授权记忆；恢复归档继续原身份。来源删除后重建的新对象不能复活旧证据。

确认来源删除后：

1. 原子发布来源墓碑或检索失效标记，立即阻止仅由该来源支持的派生内容参与检索和画像。
2. 使片段摘要和依赖投影失效，重算关联画像。
3. 有其他有效证据的事实保留，移除被删除的证据；仅有失效证据的未确认候选自动清理。
4. 本人确认过且失去全部来源的记忆进入待确认，批量显示「来源已删除，是否一并遗忘」。

待确认操作为「删除关联记忆」和「保留为独立记忆」。保留需显式确认，记忆标记原来源已删除，不能继续展示为可验证引用。待确认期间默认不进入普通检索，避免提示未处理时继续使用失效信息。

提供独立的「彻底遗忘」命令，清理指定范围的派生记忆、片段摘要、画像依赖、缓存与未来索引，并使未完成任务的提交失效。彻底遗忘有持久回执及清理状态，崩溃后继续同一操作。共享事实删除关联证据后重新评估；若用户指定遗忘该事实，则同时阻止其他来源再次自动提取，撤销该决定需显式操作。

遗忘不能承诺删除已交付的外部导出、云服务已处理的数据或已提交任务的历史快照。界面应显示本系统实际清理范围与保留策略；本地可控副本纳入清理流程。审计记录保留必要操作事实，不能保留被要求遗忘的正文。

## 长会话分析

会话按完整轮次分块，采用片段提取、会话汇总、画像聚合的分层流程。首次分析逐页读取，每个任务设置 token、页数、时间和费用预算；达到预算后保存检查点并显示覆盖范围，后续继续处理，不能把截断历史标为分析完成。

| 消息内容 | 证据策略 |
| --- | --- |
| 用户明确陈述 要求 纠正 | 画像 偏好 目标的主要证据；区分长期规则与当前任务 |
| 用户引用的文档 邮件 代码 | 标记引用内容，识别实际主体，不自动认作用户观点 |
| Assistant 建议和推测 | 不直接成为个人事实 |
| 用户明确接受的方案 | 可成为决策，引用接受该方案的用户消息及对应方案 |
| 工具和执行结果 | 仅用于验证结果与完成状态，提取必要结论 |
| 思考内容 重复日志 大量代码 | 默认不进入个人记忆 |

仅分析用户指令会漏掉已接受方案和实际结果；无差别分析全部内容会引入模型推测和无关日志。提取时保存证据类别及主体，例如「长期使用中文」与「本次用中文回复」分别处理。

增量分析保存原生 Session、分支、turn、message 或 item 身份与内容 hash。新增轮次只分析新增内容；编辑旧消息、重新生成或分支变化使对应片段及后续依赖摘要失效。历史游标表示读取进度，不天然保证旧消息从未变化，须结合来源版本与必要核对。

正在生成的轮次作为临时数据，完成或达到配置的稳定条件后才能提交持久记忆。外部 harness 无可靠完成事件时记录「截至某一来源版本」的覆盖范围，不能用近期活跃推测代替完成证据。

父子 Session 与分支共享前缀时按原生身份及引用关系去重；复制历史不增加独立证据数量。原生平台已经压缩或省略的历史标记覆盖限制，不补造原始证据。每层摘要保留对应片段和版本引用，来源删除可精确失效。

## Pot 与 Agent

Pot 是持续关注来源与目标的服务实例，Agent 定义具体任务的分析和执行方式。主动性来自触发与调度策略；Agent 同样可以被调度器主动调用。

| 维度 | Agent | Pot |
| --- | --- | --- |
| 定义重点 | 如何完成某类任务 | 持续关注谁 哪些目标 哪些来源 |
| 生命周期 | 配置可长期存在，执行按任务发生 | 服务实例长期存在，保存进度与待办 |
| 触发 | 用户 Flow 调度器调用 | 来源变化 完成通知 定时规则 用户调用 |
| 状态 | 当前任务及执行上下文 | 来源水位 目标 待确认 触发记录 |
| 关系 | 执行提取 归纳 规划 | 判断触发条件并调用 Agent 或 Flow |

新增 PotDefinition，引用现有执行引擎。第一期只有一个分身管家 Pot，不引入多 Pot 协作、独立模型通信栈或单独的执行内核。分析任务与用户原 Session 的运行和控制所有权分离，不通过 resume harness 读取历史。

职责描述可以进入提示词，来源授权、触发、预算、去抖、并发、失败重试与行动权限由宿主按结构化配置执行。默认主动操作为整理候选、更新投影和站内建议；发送邮件、修改外部文件等需单独配置授权及必要交互。

来源变化按对象去抖，预算与并发有界，避免流式会话每个 delta 触发分析。派生数据保存于独立存储，并从来源监听中排除，防止分身写入触发自身无限循环。只有宿主或后台服务运行时才执行任务；持久触发不等于浏览器关闭后仍有执行进程。

## 状态与恢复

对象状态独立记录，配置是否启用不与当前执行状态混用。

| 对象 | 状态与进度 |
| --- | --- |
| Pot 配置 | enabled paused；策略 revision Agent Flow 来源 触发 预算 行动权限 |
| Pot 运行 | idle queued working waiting-review failed；当前任务 最后成功时间 下一次触发 |
| 来源 | available changed inaccessible deleted revoked；内容版本 完整扫描代次 |
| 分析任务 | queued reading extracting committing succeeded failed cancelled；游标 租约 fence 回执 重试 |
| 记忆 | candidate active disputed superseded unsupported forgotten；证据 有效时间 敏感范围 |
| 人工决定 | confirmed corrected rejected retained forgotten；对象版本与适用范围 |
| 清理任务 | pending invalidated cleaning completed failed；操作身份及剩余范围 |

提交检查目标来源 incarnation、内容版本、授权版本、遗忘代次及当前人工决定。旧任务不能覆盖新版本，也不能在来源删除、撤权或用户拒绝后重新写入。来源不可访问时保留任务进度，采取有界退避，不将暂时失败转为删除。

同一事务存储可将授权校验、证据与记忆更新、检查点和回执一起提交。跨存储使用持久 outbox 与幂等消费者，先使来源不可用于检索，再推进派生清理，不声称跨数据库原子性。复用 Durable 任务租约和预算，未知提交结果先核对回执，不盲目重放。

## 模块分工与存储

| 层 | 建议职责 |
| --- | --- |
| app-shell | 数字分身导航 视图 来源选择 审阅 遗忘与 Pot 配置交互 |
| app-core | 来源注册与适配 授权协调 增量计划 证据与画像服务 Pot 装配 |
| llm-session 共享 Memory | 记忆权威存储 条件更新 精确 scope 审计与回执 |
| llm-tasks llm-flow durable-kernel | 有预算的分析任务 检查点 租约 恢复和交互 |
| piagent-driver | 通过公开契约读取授权远程文件及原生历史，不保存个人画像 |

分身数据保存于独立 profile 资源，不放进普通 Session 生命周期或远程项目工作目录。建议新增 `/var/lib/digital-twin` 来源及调度资源，记忆引用既有独立共享 Memory。实际持久存储格式在实现时按事务能力确定，不用可任意修改的普通 JSON 文件冒充授权权威。

缓存是可重建投影，检索返回前校验当前来源、记忆版本和授权。敏感数据的落盘、缓存和备份策略须由对应平台实现；第一期不声称已提供新的加密能力。

## 实施阶段与验收

第一阶段提供数字分身导航、一个 Pot、手动选择文件及会话来源、可恢复的增量分析、画像和记忆审阅、删除核对与遗忘。第二阶段增加事件和定时触发、目标提醒、私密来源的完整处理边界。第三阶段按实际需求增加邮箱来源及专用 Pot；向量检索另立验收。

第一阶段至少覆盖：

- 修改时间未变但内容变化，内容未变但时间变化，同毫秒修改与时钟回拨。
- 完整扫描 删除外部文件 应用关闭后删除 网络失败 扫描截断 撤权及挂载断开。
- 移动 文件删除后同路径重建 Session 归档恢复 原生 Session 删除及重复派生历史。
- 长历史分页中断恢复 旧消息编辑 分支变化 预算耗尽和不完整历史覆盖说明。
